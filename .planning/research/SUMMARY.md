# Research Summary — Enterprise GitHub Portfolio

## Key Findings

**Stack:** GitHub Actions (CI), shields.io badges, Mermaid diagrams, GitHub Wiki, GitHub Releases with semantic versioning. All patterns are stable and well-understood.

**Table Stakes:** CI badge on every repo, GitHub topics, LICENSE file, non-empty READMEs with working code blocks, .gitignore excluding secrets.

**Differentiators:** Architecture diagrams (Mermaid), GitHub Wiki (4+ pages), GitHub Releases, cross-repo narrative in org profile, personal profile README.

**Watch Out For:**
- ci-autopilot's 1964 open issues — must NOT be featured in org profile
- autogen README says "starter kit" — undersells the work, must be rewritten
- Any empty wiki pages — worse than no wiki
- Failing CI badge is an immediate disqualifier
- Internal language in READMEs (references to "old project", "our fork", etc.)

## Recommended Phase Order

1. **Foundation** — Topics, org profile, LICENSE files, hide ci-autopilot noise
2. **gsd-orchestrator** — CI, Mermaid arch diagram, Wiki (4 pages), v1.0.0 release
3. **Promptimprover + autogen** — Rewrite READMEs, add CI, add Wikis
4. **Coherence** — Cross-repo links, personal profile README, final polish
